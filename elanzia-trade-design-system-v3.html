Colour

4 ramps · 40 aliases · 4 statusesLive in both themes

Two layers. Layer 1 is the ramp: 45 fixed values that are the same in light and dark. Layer 2 is the alias: 40 names that get new values in dark. A component never names a ramp step. It names a role. Write var(--action-bg), never var(--emerald-600). Break that rule once and dark mode stops working.

The 40 aliases, and what each one is for
AliasLightDark RatioApplied to

Ratio is measured against the surface each token actually sits on, in the theme now showing. Switch the theme in the bar above and every number in this table is recomputed against the new values. Nothing in this system is a claim; it is all arithmetic.

Gold has one job

Champagne Gold #E2AA28 measures 2.08:1 on Pearl White, so it can never be text on a light background. It is legal as a fill carrying Onyx at 9.38:1, as a 1px rule, or as type on emerald-900 at 7.35:1. Because the ratio forbids it, no one has to remember the rule. Where a gold-coloured word is needed, that is the attention status below, which is gold-700 at 8.36:1. Gold does not appear in dark mode as anything but a fill.

Statuses

Four statuses, each with a foreground, a background and a border. Nothing else in the interface is coloured. Both themes hold every status foreground above 5.7:1 on its own tint.

The ramps

Every family is normalised. Step 600 measures 6.52:1 on Pearl White whether it is emerald, gold, neutral or danger, so the four families are interchangeable at any step and a colour swap needs no re-checking. The numbers under each swatch are its contrast on Pearl White and on Onyx Black. Click any swatch to copy its hex.

Steps that do not appear in the alias table exist for tints and future use. Do not put one into a component without giving it an alias first.

Pills are for tags, not actions.

Status chips, filter chips, count badges, avatars and the toggle track are pills. Buttons are not. A filter chip and a button sit side by side in the same toolbar, so buttons take 8px and stay distinguishable from a tag.

Documents stay at 0. Everything the user manipulates is rounded. Everything that represents paper is square.

Cards, panels, banners and tables sit on a 1px border and cast nothing. Shadows are pure Onyx alpha, never tinted. In dark mode the same four tokens carry heavier alpha, because a shadow on a dark ground has to work harder to separate two surfaces that are already close in lightness.

Rounding says what a thing is.

Four layers, and a developer can place any new component by asking which one it belongs to. 0 is paper. 8 is the work layer, the things a user operates. 12 is the conversation layer, the things that hold a message or a group. 16 is the showcase layer and exists in the Marketplace alone. 999 is a tag, never an action.

Motion

5 durations · 3 curvesHover any row

Durations are named for what they do, not how long they take, so a developer picks one by answering a question rather than guessing a number. Everything on a trade screen is either a press, a hover, a state change or an overlay. If a movement is not one of those four, it should not be moving.

No motion carries meaning on its own. Every animation in this system has a static equivalent that says the same thing, because prefers-reduced-motion and the Reduce motion switch above both turn all of it off. Nothing becomes ambiguous when they do.

Light and dark

40 aliases remapped · 0 component changesMarketplace ships light only

Who gets which. The Marketplace, web and mobile, ships light only: it sells photographed jewellery, and a dark page changes how gold and stone read on screen. Elanzia Super Admin, Vendor Admin and Vendor Admin mobile ship both and follow prefers-color-scheme with a manual override that persists per user. That is a product decision, not a technical one, and it costs nothing to reverse.

The five rules that make dark mode arithmetic
RuleWhy, and what breaks without it
Dark is not an inversionThe page is #0A0F0E, an emerald-tinted charcoal, and the raised surface is lighter at #141A19. Light mode raises with shadow; dark mode raises with lightness. Inverting the light values gives a grey that fights the brand.
The action climbs the rampPrimary action moves from emerald-600 to emerald-400 and its label flips from Pearl White to Onyx. White on emerald-600 measures 2.9:1 against a dark page frame and reads as a hole; emerald-400 with an Onyx label measures 5.5:1 and reads as a button.
Text stops three steps earlyThe tertiary floor in dark is neutral-300 at 7.3:1. neutral-600, the light-mode floor, measures 2.9:1 on a dark page and fails. Every text alias is re-solved against the new ground, never carried over.
Status tints get their own valuesA light-mode tint at 5% opacity turns to mud on charcoal. Dark tints are separate hexes, each solved so its foreground lands within 0.1 of the light-mode ratio. Positive reads 6.20 light and 5.79 dark.
Glass does not cross overThere is no dark glass. Every glass surface falls back to --surface-raised plus --shadow-dropdown in dark. A blurred translucent panel on a dark page has no reliable contrast floor.
Implementation
<html data-theme="light">   <!-- or "dark", or absent to follow the OS -->

/* the only thing dark mode changes */
[data-theme="dark"]{ --surface-page:#0A0F0E; --action-bg:#259880; ... 40 names }

/* a component never knows which theme it is in */
.btn-primary{ background:var(--action-bg); color:var(--action-fg) }

Set the attribute on <html> before first paint, from localStorage, or the page flashes. Add <meta name="color-scheme" content="light dark"> so form controls and scrollbars follow. If a component needs a value that is not in the 40, add an alias to both themes. Never reach past the alias layer into the ramp.

Glass

Marketplace only · 4 named surfaces · light onlyDrag the tint

Glass is a tray, never a label. Text on a translucent surface changes contrast with whatever is scrolling behind it. Measured across one 900px panel, a single line of secondary text ran from 6.7:1 to 17.8:1 depending on the photograph underneath. That is not a value anyone can certify. So glass carries controls that have their own opaque fill, and primary ink only. Never secondary text, never a figure, never a status.

Over a table, a price breakup, a form, a specification plate, an invoice or a hallmark. Inside a scrolling list. More than four instances on one screen. In any admin console. In dark mode. On anything a user reads a number from.

Three escape hatches, all automatic. prefers-reduced-transparency, the Solid surfaces switch in the bar above, and data-theme="dark" each replace every glass panel with --surface-raised and a dropdown shadow. The layout does not move when they do, because the panel keeps its box.
